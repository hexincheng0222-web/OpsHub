设计方案：机柜显示优化

基于方案 B（组件拆分），以下是具体设计

一、组件拆分

组件架构
src/components/devices/
├── RackCard.vue        ← 机柜容器（头部 + U位网格 + 底座）
├── RackHeader.vue      ← 机柜名称 + 楼层标签 + 统计信息
├── RackStats.vue       ← 总U / 已用U / 设备数 / 利用率进度条
├── RackGrid.vue        ← U位网格（动态行数 grid-template-rows）
├── USlot.vue           ← 单个U位（空位 / 设备占位）
├── DeviceCard.vue      ← 设备卡片（名称、IP、型号、状态LED、U标签）
├── DeviceForm.vue      ← 新增/编辑设备表单
└── useDragDrop.ts      ← 拖拽 composable（鼠标事件 + 放置逻辑）

DevicesView.vue 只保留：楼层筛选 + 机柜列表渲染 + 统计面板

二、机柜动态高度

高度计算逻辑
每个 U 位高度 = 20px（固定）

42U 机柜 → grid-template-rows: repeat(42, 20px) → 高度 840px
24U 机柜 → grid-template-rows: repeat(24, 20px) → 高度 480px
12U 机柜 → grid-template-rows: repeat(12, 20px) → 高度 240px

U 编号：顶部 = 最大U值，底部 = U1（倒序排列）

四、拖拽系统重写

useDragDrop.ts 核心逻辑
修复要点：

1. 选择器修复
   .rack-container → .rack-card
   .rack-title → .rack-name

2. data 属性
   每个 .u-slot 添加 data-rack-id 和 data-u-offset
   通过 el.dataset 读取，不用 textContent

3. 拖拽流程
   mousedown → 记录源设备 + 源机柜
   mousemove → 计算目标U位，高亮放置区
   mouseup   → 验证合法性 → 调用 store.moveDevice()

4. 合法性检查
   目标 U 位必须空闲（无设备占用）
   多U设备的起始位置 + U跨度不能越界
   跨机柜移动时自动重建 compact 数组
