## 二、P0 修复（数据完整性 + 安全，必修）

### P0-1 外键启用 + device_types 迁移脱钩【原高#5】

**文件**：`server/db.ts`

**现状根因**：
1. 全文无 `PRAGMA foreign_keys = ON`，better-sqlite3 默认关闭外键 → 所有 `REFERENCES ... ON DELETE CASCADE/SET NULL` 声明失效，删机柜后 `rack_slots` orphan 永久残留，`printer_models`/`phone_models`/`toner_models`/`manual_docs` 级联均不生效
2. `device_types` 迁移（L558-575）在无 `key` 列时 `DROP TABLE` 重建为空表，而 seed 块（L681）嵌在 `if (floorCount.cnt === 0)`（L673）内——当 `device_floors` 已有历史数据时 seed 块被跳过，`device_types` 永久清空且不重填

**修复方案**：

```ts
// server/db.ts 顶部（紧跟 db 初始化之后，所有 CREATE TABLE 之前）
db.exec('PRAGMA foreign_keys = ON')
console.log('[db] 已启用外键约束（CASCADE/SET NULL 生效）')
```

device_types 迁移脱钩——把 seed 块从 `floorCount` 内拆出，独立判断 `device_types` 是否为空。

**实测代码结构**（`server/db.ts` L673-700）：迁移块（L558-578）与 seed 块（L673-700）已分离，但 seed 块把楼层 + device_types + device_models **全包在一个 `db.transaction(() => {...})` 内**，gate 条件是 `if (floorCount.cnt === 0)`。迁移把 `device_types` DROP 重建为空表后，若 `device_floors` 已有数据 → `floorCount.cnt !== 0` → 整个 transaction 跳过 → device_types 不重填。

改造时**保留 transaction 原子性**，把 gate 条件从「楼层为空」拆成各自独立的 count 判断：

```ts
// server/db.ts 现有 L673-700 区域改造
const floorCount = db.prepare('SELECT COUNT(*) as cnt FROM device_floors').get() as { cnt: number }
const dtCount = db.prepare('SELECT COUNT(*) as cnt FROM device_types').get() as { cnt: number }
const dmCount = db.prepare('SELECT COUNT(*) as cnt FROM device_models').get() as { cnt: number }

// 三组 seed 都包在一个 transaction 内保持原子性，但 gate 各自独立
const seedDicts = db.transaction(() => {
  // 楼层（仅当为空）
  if (floorCount.cnt === 0) {
    const insertFloor = db.prepare('INSERT INTO device_floors (name, sort_order) VALUES (?, ?)')
    const floors = ['-1F', '1F', '2F', '3F', '4F']
    floors.forEach((f, i) => insertFloor.run(f, i))
    console.log('[db] 已初始化 5 条楼层')
  }

  // 设备类型（仅当为空——脱钩于 floorCount，修复迁移 DROP 后不重填 bug）
  if (dtCount.cnt === 0) {
    const insertType = db.prepare('INSERT INTO device_types (key, name, abbr, icon, color, sort_order) VALUES (?, ?, ?, ?, ?, ?)')
    const types: [string, string, string, string, string, number][] = [
      ['server', '服务器', 'SV', 'Monitor', '#3fb950', 0],
      ['switch', '交换机', 'SW', 'Connection', '#58a6ff', 1],
      ['storage', '存储', 'ST', 'Coin', '#a371f7', 2],
      ['router', '路由器', 'RT', 'Share', '#d29922', 3],
      ['firewall', '防火墙', 'FW', 'Shield', '#f85149', 4],
      ['ups', 'UPS', 'UP', 'Lightning', '#e06c75', 5],
      ['pdu', 'PDU', 'PD', 'Plug', '#6e7681', 6],
    ]
    types.forEach(t => insertType.run(...t))
    console.log('[db] 已初始化 7 条设备类型')
  }

  // 设备型号（仅当为空——同样脱钩）
  if (dmCount.cnt === 0) {
    // ... 原 device_models seed 代码移到这里（保留原有 models 数组）
    console.log('[db] 已初始化 N 条设备型号')
  }
})
seedDicts()
```

**关键**：原代码把所有 seed 套一个 `if (floorCount.cnt === 0)` 是 bug 根源——迁移 DROP device_types 后即便 `device_floors` 有数据，`device_types` 也需要重填。改造后三组 seed 各自看自己的 count 判断，互不牵连，但仍在同一个 transaction 内保持原子性。

**验证点**：
- 启动日志含「已启用外键约束」
- 删一个被引用的 rack 后，`rack_slots` 对应行自动 CASCADE 删除
- 持旧库（有 device_floors 数据但 device_types 无 key 列）升级后，device_types 表有 7 条 seed 数据
- `sqlite3 data/opshub.db "PRAGMA foreign_keys"` → 返回 1

**风险**：启用外键后，原有 orphan 数据可能在下次删除时触发 CASCADE——建议升级前先跑一次 `DELETE FROM rack_slots WHERE device_id IS NOT NULL AND device_id NOT IN (SELECT id FROM devices)` 清理 orphan。

### P0-3 OperationsView doc.title XSS 转义【原高#3】

**文件**：`src/views/OperationsView.vue` L433/441/462/482

**现状根因**：`doc.title` 未 HTML 转义直接拼进 `document.write`，标题含 `<img src=x onerror=...>` 时 XSS。
```ts
w.document.write(`<!doctype html><html><head><meta charset="utf-8"><title>${doc.title}</title>`)
//                                                                                       ↑ 未转义
```

**修复方案**：新增 `escapeHtml` 工具函数，所有 `doc.title` 拼接点改用转义值：

```ts
// src/views/OperationsView.vue 顶部 script 区
function escapeHtml(s: string): string {
  return String(s ?? '').replace(/[&<>"']/g, c => ({
    '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;'
  }[c]!))
}
```

修改 4 处拼接点：
```ts
// L433
w.document.write(`<!doctype html><html><head><meta charset="utf-8"><title>${escapeHtml(doc.title)}</title>`)
// L441
</style></head><body><h1>${escapeHtml(doc.title)}</h1>${renderedContent.value}</body></html>`)
// L462
<title>${escapeHtml(doc.title)}</title>
// L482
<h1>${escapeHtml(doc.title)}</h1>
```

**注意**：L452/486/490 的 `filename = doc.title + '.md'` 用作文件名，**不要转义**（转义后文件名含 HTML 实体），但要 sanitize 文件名特殊字符：

```ts
// 文件名 sanitize（防止路径穿越 + 非法文件名字符）
function sanitizeFilename(s: string): string {
  return String(s ?? '').replace(/[<>:"/\\|?*]/g, '_').slice(0, 100) || 'document'
}
// L452/486/490
filename = sanitizeFilename(doc.title) + '.md'
```

**验证点**：标题含 `<script>alert(1)</script>` 时，导出 .doc 文件内 `<title>&lt;script&gt;alert(1)&lt;/script&gt;</title>`，无脚本执行

### P1-2 formatTime 时区偏差【原中#8】

**文件**：`src/utils/format.ts` L6-11

**现状根因**：DB 用 `datetime('now')`（UTC）存储，前端 `new Date(time).toLocaleString('zh-CN', { hour12: false })` 对无时区后缀的 ISO 字符串按本地时间解析再本地时区显示，UTC+8 用户看到的时间比真实晚 8 小时。

**修复方案**：显式指定 UTC 时区，让 Date 把无后缀字符串当 UTC 解析再转本地显示：

```ts
// src/utils/format.ts
export function formatTime(time: string | number | undefined | null): string {
  if (!time) return '—'
  const d = new Date(time)
  if (isNaN(d.getTime())) return '—'
  // DB 用 datetime('now') 存 UTC 时间，无时区后缀。
  // 显式 timeZone: 'UTC' 让 toLocaleString 把无后缀字符串当 UTC 取值，
  // 再转本地时区显示——UTC 08:00 在 UTC+8 用户看到 16:00
  return d.toLocaleString('zh-CN', { hour12: false, timeZone: 'Asia/Shanghai' })
}
```

注：`new Date('2026-07-12 08:00:00')`（无后缀）在 ES2015+ 按本地时间解析，已经是本地时间——所以问题在于 DB 存的是 UTC 但 Date 当本地解析。更稳妥的方案是在前端解析时补 `Z` 后缀：

```ts
export function formatTime(time: string | number | undefined | null): string {
  if (!time) return '—'
  // DB datetime('now') 返回 'YYYY-MM-DD HH:MM:SS'（UTC，无时区后缀）
  // 补 'Z' 让 Date 按 UTC 解析，再 toLocaleString 转本地时区显示
  const iso = typeof time === 'string' && !/[zZ]|[+-]\d{2}:?\d{2}$/.test(time)
    ? time.replace(' ', 'T') + 'Z'
    : time
  const d = new Date(iso)
  if (isNaN(d.getTime())) return '—'
  return d.toLocaleString('zh-CN', { hour12: false, timeZone: 'Asia/Shanghai' })
}
```

**验证点**：DB 存 `2026-07-12 08:00:00`（UTC），UTC+8 用户看到 `2026/7/12 16:00:00`

### P3-2 printer-table-helper cache TTL + key 全字段【原中#11】

**文件**：`src/utils/printer-table-helper.ts` L29、L112-115

**现状根因**：`floorGroupsCache` 模块级 Map 无 TTL（内存泄漏）；cache key 只含 `id + status`，不含 `manufacturer/model/location/tonerModel/notes`，编辑打印机后刷新命中旧缓存显示陈旧分组。

**修复方案**：

```ts
// src/utils/printer-table-helper.ts
const floorGroupsCache = new Map<string, { result: FloorGroup[]; ts: number }>()
const CACHE_TTL = 30_000  // 30 秒

export function buildFloorGroups(printers, selectedFloors, searchQuery, statusFilter = ''): FloorGroup[] {
  // key 加入全部参与排序分组的字段
  const hash = JSON.stringify([
    printers.map(p => `${p.id}|${p.status}|${p.manufacturer}|${p.model}|${p.location}|${p.tonerModel}|${p.notes}`).join(','),
    selectedFloors instanceof Set ? [...selectedFloors].sort().join(',') : (selectedFloors || ''),
    searchQuery,
    statusFilter,
  ])
  const cached = floorGroupsCache.get(hash)
  if (cached && Date.now() - cached.ts < CACHE_TTL) return cached.result
  const result = computeFloorGroups(printers, selectedFloors, searchQuery, statusFilter)
  floorGroupsCache.set(hash, { result, ts: Date.now() })
  // 清理过期 key（避免内存泄漏）
  if (floorGroupsCache.size > 100) {
    for (const [k, v] of floorGroupsCache) {
      if (Date.now() - v.ts > CACHE_TTL) floorGroupsCache.delete(k)
    }
  }
  return result
}
```

### P3-8 parseXlsx 合并单元格/日期处理【原低#6】

**文件**：`src/utils/excel.ts` L31-42

**现状根因**：`sheet_to_json(ws, { header: 1, defval: '' })` 合并单元格只保留首单元格值其余空、日期单元格返回 Excel 序列号数字（如 `45300.5`）而非格式化日期、行数组长度不足 header 时不补齐。

**修复方案**：

```ts
// src/utils/excel.ts parseXlsx 改造
export async function parseXlsx(file: File): Promise<{ headers: string[]; rows: string[][] }> {
  const buf = await file.arrayBuffer()
  const wb = XLSX.read(buf, { type: 'array', cellDates: true })  // ← cellDates: 让日期单元格返回 Date 对象而非序列号
  const ws = wb.Sheets[wb.SheetNames[0]]
  const aoa: unknown[][] = XLSX.utils.sheet_to_json(ws, { header: 1, defval: '', raw: false })
  // raw: false 让日期按 cellText 格式化（YYYY-MM-DD），合并单元格 defval 补空
  if (aoa.length === 0) return { headers: [], rows: [] }
  const headers = (aoa[0] as unknown[]).map(c => String(c ?? '').trim())
  const colCount = headers.length
  const rows = aoa.slice(1).map(r => {
    const arr = (r as unknown[]).map(c => {
      if (c instanceof Date) return c.toISOString().slice(0, 10)  // Date → YYYY-MM-DD
      return String(c ?? '').trim()
    })
    // 补齐长度不足 header 的行
    while (arr.length < colCount) arr.push('')
    return arr.slice(0, colCount)
  })
  return { headers, rows }
}
```

**验证点**：导入带合并单元格/日期列/缺列的 xlsx，合并单元格补空、日期显示 YYYY-MM-DD、行长度与 header 一致

## 八、风险评估

### P0-1 外键启用风险

启用 `PRAGMA foreign_keys = ON` 后，**已有 orphan 数据**可能在下次删除时触发 CASCADE 误删。建议升级前先跑清理：

```sql
-- 升级前清理 orphan（备份 DB 后执行）
DELETE FROM rack_slots WHERE device_id IS NOT NULL AND device_id NOT IN (SELECT id FROM devices);
DELETE FROM rack_slots WHERE rack_id NOT IN (SELECT id FROM racks);
DELETE FROM printer_models WHERE brand_id NOT IN (SELECT id FROM printer_brands);
DELETE FROM phone_models WHERE brand_id NOT IN (SELECT id FROM phone_brands);
DELETE FROM toner_models WHERE brand_id NOT IN (SELECT id FROM printer_brands);
DELETE FROM services WHERE host_id IS NOT NULL AND host_id NOT IN (SELECT id FROM service_hosts);
-- 其余 REFERENCES 同理
```

### P1-2 时区修复风险

补 `Z` 后缀方案会让**所有历史时间显示 +8 小时**——如果用户之前习惯了错误显示，修复后会感觉时间"跳了"。建议在 release notes 说明。

### P2-3 并发限流风险

限流 5 是经验值，设备数 50+ 时单轮调度耗时可能从 `<1s` 变成 `10s+`（5 并发 × 10 设备串行）。如果调度间隔短（如 60s），需观察是否来得及。可把限流数做成 config 项。
